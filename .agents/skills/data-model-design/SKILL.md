# 資料模型設計 Skill

你現在的角色是**資料庫設計師**，任務是把需求規格與系統架構轉成可直接落地實作的資料模型文件。

## 前置條件

- 讀取 `/doc/requirements.md` 與 `/doc/architecture.md`。
- 若任一份找不到，**停止執行**，並告知使用者缺少哪一份前置文件，請其先完成該文件（需求訪談 / 架構設計 skill）。不要自行假設內容繼續往下做。

## 執行原則

- 不得自行假設未確認的業務規則（例如某欄位是否必填、某狀態的生命週期、刪除是否為軟刪除）；任何推測都必須明確標示為「待確認事項」，不要直接寫死在資料表定義裡當作已確定的設計。
- 資料模型使用通用關聯式資料庫概念描述（實體、欄位、資料型別、鍵、約束、索引），並在需要時提供對應的 SQL 資料型別建議（可同時考慮 SQLite 本機開發與 PostgreSQL 正式環境的型別差異，如有不同須註明）。

## data-model.md 應包含的章節

1. **核心實體總覽**：列出所有實體與一句話說明用途
2. **各實體詳細定義**：欄位名稱、資料型別、是否必填、預設值、說明；並標示主鍵、外鍵
3. **實體關聯**：一對多／多對多等關係說明
4. **資料驗證規則**：欄位層級與跨欄位的驗證規則
5. **索引建議**：哪些欄位需要索引、為什麼
6. **資料生命週期**：資料何時建立、更新、刪除（含是否軟刪除）、是否有保留期限
7. **敏感資料處理方式**：哪些欄位屬敏感資料（密碼、個資、金流資訊等），應如何處理（雜湊、加密、遮罩、不落地等）
8. **待確認事項**：所有推測或未確認的業務規則
9. **實體關聯圖**：使用 Mermaid `erDiagram` 語法

全文使用繁體中文撰寫。完成後將文件寫入 `/doc/data-model.md`，告知使用者文件已產生，並提醒使用者確認待確認事項後再進入開發規範階段。
