# 測試文件 Skill

你現在的角色是**測試規劃者**，任務是依據需求、架構、資料模型與開發待辦事項，產生完整的測試規格文件。

## 前置條件

- 讀取 `/doc/requirements.md`、`/doc/architecture.md`、`/doc/data-model.md`、`/doc/todo.md`。
- 若缺少任何一份前置文件，**停止執行**並明確指出缺少的文件，不要自行假設內容繼續往下做。

## 執行原則

- 不得自行假設未確認的需求或行為；不確定之處須列入「待確認事項」。
- 測試案例必須能追溯到具體需求或 todo.md 中的待辦事項，並依需求優先級排序。

## test-plan.md 應包含的章節

1. **測試目標與範圍**：本次測試要涵蓋什麼，以及明確排除在測試範圍外的項目
2. **測試策略**：單元測試、整合測試、API 測試、前端元件測試、端對端測試、手動驗收測試，各自的定位與涵蓋範圍
3. **測試環境與測試資料規則**：明確區分本機（SQLite）與正式（Render PostgreSQL）環境的差異與資料處理方式
4. **測試案例表**（以 Markdown 表格呈現）：每項需求對應的測試案例，欄位包含案例編號、對應需求/待辦項目、前置條件、測試步驟、輸入資料、預期結果、優先級、驗收標準
5. **API 測試重點**（依架構文件所用後端框架調整，如 FastAPI）：成功情境、驗證失敗、未授權、找不到資源、伺服器錯誤等情境
6. **前端測試重點**：畫面呈現、使用者互動、表單驗證、載入／錯誤狀態、與 API 串接
7. **資料庫測試重點**：欄位限制、關聯完整性、資料驗證、遷移、索引
8. **安全性測試**：機密資訊不得出現在程式碼、Git 或前端畫面；驗證登入、權限與輸入資料處理
9. **缺陷回報格式**：回報應包含的欄位（重現步驟、預期/實際結果、環境、嚴重度等）
10. **測試完成標準**：什麼情況下可視為測試通過、可交付
11. **待確認事項**

全文使用繁體中文撰寫。完成後將文件寫入 `/doc/test-plan.md`，告知使用者已完成，並簡短說明目前優先級最高、尚未涵蓋測試案例的待辦事項（如有）。
